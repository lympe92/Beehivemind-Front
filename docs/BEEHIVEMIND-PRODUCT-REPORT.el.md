## 1. Τι είναι το BeehiveMind

**Το BeehiveMind είναι μια πλατφόρμα διαχείρισης κυψελών για επαγγελματίες μελισσοκόμους.** Συνδυάζει τρία προϊόντα που μοιράζονται έναν λογαριασμό και ένα backend:

| Προϊόν | Τι είναι | Ποιος το χρησιμοποιεί |
|---|---|---|
| **BeehiveMind Web** (`beehivemind.tech`) | Το δημόσιο site συν το dashboard του μελισσοκόμου (μελισσοκομεία, κυψέλες, επιθεωρήσεις, ταΐσματα, συγκομιδές, θεραπείες, οικονομικά, ημερολόγιο, AI βοηθός) και ένα ξεχωριστό admin panel για το προσωπικό | Μελισσοκόμοι (desktop/tablet) και προσωπικό BeehiveMind |
| **BeehiveMind Mobile** (εφαρμογή Android, package `org.beehivemind`) | Εφαρμογή πεδίου με φωνητικές εντολές: περιγράφεις μια κυψέλη φωναχτά ενώ τα χέρια σου είναι μέσα της, και η επιθεώρηση καταγράφεται και συγχρονίζεται αργότερα | Μελισσοκόμοι στο μελισσοκομείο |
| **BeehiveMind API** (`api.beehivemind.tech`) | Το backend σε Laravel που αποθηκεύει όλα τα δεδομένα και τρέχει τη μηχανή διάγνωσης (Rules Engine), τη μηχανή τάσεων (Trend Engine), τον LLM βοηθό, τον καιρό, τις ειδοποιήσεις και τα εργαλεία διαχείρισης | Και οι δύο clients |

**Τοποθέτηση όπως δηλώνεται στο site:** «Most intelligent beekeeping software» — «Increase your business productivity with our beehive management software». Τρία σημεία απόδειξης: *Records with no signal · Hands stay in the hive · Android and iOS* (καταγραφή χωρίς σήμα · τα χέρια μένουν στην κυψέλη · Android και iOS).

**Βασική υπόσχεση:** καταγράφεις κάθε επιθεώρηση με τη φωνή σου στο χωράφι, τα δεδομένα εμφανίζονται ως καθαρός πίνακας και γραφήματα στο web, και η πλατφόρμα μετατρέπει το ιστορικό σε διαγνώσεις, τάσεις, προγράμματα θεραπειών και οικονομική εικόνα.

**Λεξιλόγιο του domain (χρησιμοποιείται με συνέπεια σε όλα τα προϊόντα):**

| Όρος | Σημασία |
|---|---|
| **Μελισσοκομείο** (apiary) | Μια τοποθεσία με συντεταγμένες GPS που φιλοξενεί πολλές κυψέλες |
| **Κυψέλη** (beehive) | Μία κυψέλη, ανήκει σε ένα μελισσοκομείο, αναγνωρίζεται από αριθμό/όνομα και ένα UUID (χρησιμοποιείται για ετικέτες QR) |
| **Βασίλισσα** (queen) | Κάθε κυψέλη έχει εγγραφή βασίλισσας: έτος, φυλή, μαρκαρισμένη ή όχι, επιθετικότητα, προέλευση (αγορά / παραφυάδα / σμήνος), ημερομηνία εγκατάστασης, σημειώσεις |
| **Ομάδα κυψελών** (beehive group) | Ομαδοποίηση κυψελών με κοινά χαρακτηριστικά που ορίζει ο χρήστης (π.χ. αγορασμένες βασίλισσες, νέες κυψέλες) |
| **Επιθεώρηση** (inspection) | Καταγεγραμμένος έλεγχος κυψέλης: 14 μετρήσεις (βλ. §3.4) |
| **Τάισμα** (feeding) | Εγγραφή ταΐσματος: τύπος, τροφή, ποσότητα, μονάδα |
| **Συγκομιδή** (harvest) | Συγκομιδή προϊόντος: μέλι / γύρη / βασιλικός πολτός / πρόπολη, ποσότητα, μονάδα |
| **Τύπος θεραπείας** (treatment type) | Επαναχρησιμοποιήσιμος ορισμός θεραπείας (π.χ. σκεύασμα για βαρρόα με δόση, μεσοδιάστημα και επαναλήψεις) |
| **Συνεδρία θεραπείας** (treatment session) | Ένας τύπος θεραπείας που εφαρμόζεται από μια ημερομηνία έναρξης σε ένα σύνολο κυψελών· αναλύεται σε χρονολογημένες **δόσεις** (treatment instances) |
| **Κόστος / κατηγορία κόστους** | Οικονομικές εγγραφές· κάθε κατηγορία είναι τύπου *έσοδο* ή *έξοδο* |
| **Υπάλληλος** (employee) | Λογαριασμός προσωπικού για το admin panel (ρόλοι: support, moderator, admin, superadmin), διαφορετικός από τον χρήστη-μελισσοκόμο |

## 2. Τεχνολογική επισκόπηση

### 2.1 Web (`beehivemind-Front`)
- **Angular 21** (standalone components, signals, lazy-loaded routes), **NgRx** store/effects, **Angular CDK** dialogs.
- **Server-side rendering** (`@angular/ssr` σε Express) με client hydration και store hydration — το δημόσιο site αποδίδεται πλήρως στον server για SEO.
- **Google Maps** (χάρτης μελισσοκομείων, map picker), **ApexCharts** (dashboards), **qrcode** (ετικέτες QR κυψελών).
- Google Analytics 4 και Google Tag Manager είναι ενσωματωμένα (`G-93PRS27RL6`, `GTM-TL4DLVB8`).
- Τα SEO metadata ανά route ορίζονται κεντρικά (`seo.config.ts`): title, description, focus keyword, canonical, robots, Open Graph, Twitter card και JSON-LD schema (`WebSite`, `WebPage`, `CollectionPage`, `AboutPage`, `ContactPage`). Locale `en_US`· το UI του προϊόντος είναι **μόνο αγγλικό**.
- Ένα μεταφερμένο design system (ένα accent χρώμα #f69520, ink #212121, βάρη 400/500/700) εφαρμόζεται αυτούσιο· αυτοματοποιημένος έλεγχος προσβασιμότητας/οπτικής πιστότητας τρέχει στα 375/768/1024/1440 px.

### 2.2 Backend (`BEEHIVEMIND-Laravel`)
- **Laravel 12**, PHP 8.2, **Laravel Passport** (OAuth2 tokens), **Horizon** (ουρές), Redis, **Google2FA** (TOTP).
- Modular monolith: `api/BeehiveMind/{Module}` για **Admin, AI, Apiaries, Auth, Beehives, Costs, Notifications, Records, Rules, Treatments, Trends, Weather**.
- REST JSON API κάτω από `/api`, payloads σε snake_case, ενιαίος φάκελος απάντησης `{ success, data, ... }`, server-side pagination.
- Auth: httpOnly cookie για το web (`access_token` / `employee_token`) **ή** bearer token (mobile)· rate limiting στα endpoints ταυτοποίησης (10/λεπτό ανά IP), κλείδωμα λογαριασμού μετά από αποτυχημένες προσπάθειες, έλεγχοι κωδικού σταθερού χρόνου.
- Εξωτερικές υπηρεσίες: **Tomorrow.io** (καιρός), **Ollama / llama3.1:8b** (AI βοηθός), **Anthropic Claude Haiku 4.5** (αξιολόγηση απαντήσεων AI), **Google Identity** (σύνδεση).
- Προγραμματισμένες εργασίες: `notifications:generate` καθημερινά στις 08:00, `passport:purge` καθημερινά, Horizon snapshots κάθε 5 λεπτά.

### 2.3 Mobile (`beehivemind-Mobile`)
- **Ionic 8 + Angular 21 + Capacitor 8**, Android-first (minSdk 24, target 36). Το iOS είναι προγραμματισμένο, όχι διαθέσιμο.
- Native plugins: `@capacitor-community/speech-recognition` (αναγνώριση ομιλίας στη συσκευή, `en-US`), `@capacitor/preferences` (τοπική αποθήκευση), `@capacitor/network` (συγχρονισμός όταν υπάρχει σύνδεση), `@capgo/capacitor-social-login` (Google), haptics, keyboard, status bar.
- Ξαναγράψιμο της αρχικής native εφαρμογής Android του 2019 (ίδιο Play Store id `org.beehivemind`)· η φωνητική γραμματική και η λογική του domain μεταφέρθηκαν σε TypeScript.
- Επικοινωνεί με το ίδιο Laravel API με bearer token αποθηκευμένο στη συσκευή.

### 2.4 Η ροή δεδομένων σε μία εικόνα

## 3. Το web dashboard του μελισσοκόμου (`/user/…`)

Κάθε συνδεδεμένος μελισσοκόμος προσγειώνεται στο dashboard. Πλοήγηση στην αριστερή μπάρα: **Dashboard · To-Do (List, Calendar) · Apiaries (List, Details, Map) · Beehives · Treatments (Create Treatments, Treatment Sessions) · Inspections · Feeding · Harvest · Financials · AI Assistant · Profile**. Στην κεφαλίδα υπάρχει καμπανάκι ειδοποιήσεων.

### 3.1 Dashboard (`/user/dashboard`)
- Γραφήματα αναλυτικών επιθεωρήσεων (γραμμή / μπάρες / πίτα μέσω ApexCharts) από τα endpoints μέσων όρων επιθεωρήσεων.
- Φίλτρο **χρήστης (όλα) → μελισσοκομείο → κυψέλη**· το επίπεδο φίλτρου καθορίζει ποιο endpoint γραφήματος καλείται.
- **Σύνοψη ανίχνευσης ασθενειών**: πλήθος κυψελών με βαρρόα, αμερικανική σηψιγονία, ευρωπαϊκή σηψιγονία και νοσεμίαση με βάση την *τελευταία επιθεώρηση ανά κυψέλη* (σε επίπεδο χρήστη/μελισσοκομείου) ή Ναι/Όχι για μία κυψέλη.

### 3.2 Μελισσοκομεία (`/user/apiary`, `/details`, `/map`, `/:id`)
- **Λίστα**: σελιδοποιημένος πίνακας μελισσοκομείων με προσθήκη / επεξεργασία / διαγραφή. Η δημιουργία ανοίγει φόρμα με **Google Maps click-to-place picker** για τις συντεταγμένες, συν όνομα, αριθμό κυψελών, προαιρετικό κείμενο τοποθεσίας και ημερομηνία ίδρυσης. Διπλά ονόματα απορρίπτονται.
- **Λεπτομέρειες**: προβολή καρτών με πλήθος εκκρεμών εργασιών ανά μελισσοκομείο.
- **Χάρτης**: όλα τα μελισσοκομεία πάνω σε Google Map.
- **Προβολή μελισσοκομείου** (dashboard ενός μελισσοκομείου): κεφαλίδα με Edit, **κάρτα καιρού** για τις συντεταγμένες του, πλακίδια «Hives» και «Pending to-dos», πίνακας πρόσφατων επιθεωρήσεων και οι συνεδρίες θεραπείας του μελισσοκομείου με γραμμές ανά δόση.
- Η διαγραφή μελισσοκομείου διαγράφει και τις κυψέλες του.

### 3.3 Κυψέλες (`/user/beehives`)
- Φίλτρο ανά μελισσοκομείο.
- **Μαζική δημιουργία**: επιλέγεις μελισσοκομείο, δίνεις πλήθος, και δημιουργούνται τόσες αριθμημένες κυψέλες (καθεμία με δική της εγγραφή βασίλισσας) με τη μία.
- **Επεξεργασία επί τόπου** ονόματος κυψέλης και έτους βασίλισσας (≥ 2000).
- **Κωδικός QR** ανά κυψέλη (από το UUID της) με λήψη PNG — για εκτύπωση ετικετών· το API μπορεί να βρει κυψέλη από το UUID.
- Διαγραφή κυψέλης.
- Το backend υποστηρίζει επίσης **ομάδες κυψελών** και **φυλές βασιλισσών** (δημιουργία/λίστα/διαγραφή) και πλουσιότερα στοιχεία βασίλισσας· το web UI προς το παρόν εκθέτει όνομα + έτος βασίλισσας.

### 3.4 Επιθεωρήσεις (`/user/inspections`)
Η κανονική σελίδα «εγγραφών». Μια επιθεώρηση είναι μία γραμμή με **14 μετρήσεις**:

| Μέτρηση | Σημασία |
|---|---|
| Ημερομηνία | Πότε επιθεωρήθηκε η κυψέλη |
| Πλαίσια (frame_space) | Πόσα πλαίσια χωράει το κιβώτιο |
| Πληθυσμός | Πλαίσια καλυμμένα από μέλισσες |
| Γύρη | Πλαίσια αποθηκευμένης γύρης (επιτρέπονται κλάσματα) |
| Μέλι / Νέκταρ | Πλαίσια σφραγισμένου + ασφράγιστου μελιού |
| Αυγά (opened_brood) | Αυγά και ασφράγιστες προνύμφες |
| Σφραγισμένος γόνος | Καταγράφεται χωριστά ώστε να προβλέπονται οι επόμενες τρεις εβδομάδες |
| Βαρρόα | Ανιχνεύθηκε ναι/όχι |
| AFB | Αμερικανική σηψιγονία ναι/όχι |
| EFB | Ευρωπαϊκή σηψιγονία ναι/όχι |
| Νοσεμίαση | Ανιχνεύθηκε ναι/όχι |
| Βασίλισσα | Εθεάθη ναι/όχι |
| Βασιλικά κελιά | Παρουσία κελιών σμηνουργίας/αντικατάστασης |
| Έτος βασίλισσας | Έτος της βασίλισσας |

- Φίλτρο δύο επιπέδων (μελισσοκομείο → κυψέλη), προσθήκη/επεξεργασία μέσω schema-driven modal με αλληλοεξαρτώμενα selects μελισσοκομείου → κυψέλης, διαγραφή με επιβεβαίωση.
- Μία επιθεώρηση ανά κυψέλη ανά ημερομηνία (έλεγχος διπλοεγγραφής σε client και βάση).
- Η αποθήκευση επιθεώρησης **συγχρονίζει την εγγραφή βασίλισσας** της κυψέλης (έτος βασίλισσας, ή αφαίρεση βασίλισσας όταν η τελευταία επιθεώρηση καταγράφει «no queen»).
- Η σελίδα ανοίγει απευθείας σε μία εγγραφή από το ημερολόγιο (`?id=`).
- Αναλυτικά backend: μέσοι όροι επιθεωρήσεων στον χρόνο ανά χρήστη / ανά μελισσοκομείο, επιθεωρήσεις ανά μελισσοκομείο / ανά κυψέλη (τελευταίες 360 ημέρες).
- Διαγνωστικό endpoint: `POST /inspections/{record}/analyze` τρέχει το Rules Engine (βλ. §5.1) και `POST /inspections/{record}/feedback` καταγράφει την ανατροφοδότηση του χρήστη για τη διάγνωση.

### 3.5 Ταΐσματα (`/user/feeding`)
- Εγγραφές: **τύπος ταΐσματος** (διεγερτικό / συντήρησης), **τύπος τροφής** (πίτες γύρης, σιρόπι ζάχαρης, φρέσκια γύρη, ζαχαρόπαστα/fondant, διατροφικό συμπλήρωμα), **ποσότητα**, **μονάδα** (kg, λίβρα, λίτρο, γαλόνι), ανά κυψέλη.
- Η κυψέλη είναι προαιρετική: με «All beehives» το τάισμα καταγράφεται για **κάθε κυψέλη του μελισσοκομείου** με μία ενέργεια (μαζική αποθήκευση).
- Ίδιο μοτίβο φίλτρου / modal / ελέγχου διπλοεγγραφής με τις επιθεωρήσεις.

### 3.6 Συγκομιδές (`/user/harvest`)
- Εγγραφές: **προϊόν** (μέλι, γύρη, βασιλικός πολτός, πρόπολη), προαιρετική περιγραφή μελιού (μόνο για μέλι), **συνολική ποσότητα**, **μονάδα** (kg, λίβρα, λίτρο, γαλόνι).
- Κυψέλη προαιρετική: μια συγκομιδή σε επίπεδο μελισσοκομείου **μοιράζεται ισόποσα στις κυψέλες του** από το backend (το υπόλοιπο στην τελευταία κυψέλη).
- Η στήλη «Beehive» εμφανίζεται μόνο όταν το φίλτρο είναι σε μελισσοκομείο αλλά όχι σε μία κυψέλη.

### 3.7 Θεραπείες (`/user/treatments`, `/user/treatments/details`)
- **Τύποι θεραπείας** (επαναχρησιμοποιήσιμοι ορισμοί): όνομα, ασθένεια, σκεύασμα, δόση, σημειώσεις, **μεσοδιάστημα σε ημέρες**, **επαναλήψεις**, ένδειξη επαναλαμβανόμενης. Δημιουργία / επεξεργασία / διαγραφή / «εφαρμογή».
- **Συνεδρίες θεραπείας**: επιλέγεις τύπο, ημερομηνία έναρξης, προαιρετικά μελισσοκομείο, ένα σύνολο κυψελών και σημειώσεις. Το backend **δημιουργεί κάθε δόση ως χρονολογημένη εγγραφή** (ημέρα 0, +μεσοδιάστημα, +2×μεσοδιάστημα, …· επαναλήψεις + 1 δόσεις), καθεμία με κατάσταση `planned` → `done` / `skipped` και πραγματική ημερομηνία όταν ολοκληρωθεί.
- Η λίστα συνεδριών δείχνει πρόοδο (δόσεις που έγιναν / σύνολο)· η διαγραφή τύπου διαγράφει και τις συνεδρίες του, η διαγραφή συνεδρίας αφαιρεί τις δόσεις της.

### 3.8 Λίστα εκκρεμοτήτων και Ημερολόγιο (`/user/todo/list`, `/user/todo/calendar`)
- **Λίστα εκκρεμοτήτων** = η ατζέντα: κάθε *προγραμματισμένη* δόση θεραπείας σε όλα τα μελισσοκομεία, ταξινομημένη κατά ημερομηνία, με τις εκπρόθεσμες σε κόκκινο και badge μελισσοκομείου. Το τσεκάρισμα σημειώνει τη δόση ως ολοκληρωμένη (και ανανεώνει το καμπανάκι). Προαιρετικό φίλτρο ανά μελισσοκομείο.
- **Ημερολόγιο**: μηνιαία προβολή επιθεωρήσεων ανά κυψέλη· κλικ σε γεγονός ανοίγει την επιθεώρηση.

### 3.9 Οικονομικά (`/user/financial`)
- **Κατηγορίες κόστους**: όνομα, περιγραφή, τύπος = *έσοδο* ή *έξοδο* (π.χ. βάζα, τάισμα, εργαλεία, μέλι, γύρη).
- **Κόστη**: ημερομηνία, όνομα, κατηγορία, ποσό. Πλήρες CRUD σε πίνακες.
- Γραφήματα (τελευταίοι 12 μήνες): **μηνιαία έσοδα έναντι εξόδων** (μπάρες/γραμμή), **ετήσια σύνολα**, **πίτα εσόδων ανά κατηγορία**, **πίτα εξόδων ανά κατηγορία**.
- Το site υπόσχεται επίσης φιλτραρισμένες οικονομικές αναφορές/εξαγωγές **[μη επιβεβαιωμένο — δεν υπάρχει ακόμα endpoint εξαγωγής]**.

### 3.10 AI βοηθός (`/user/ai-chat`, `/user/ai-chat/:id`)
- Συνομιλιακός βοηθός πάνω στα δεδομένα των κυψελών του χρήστη. Πλαϊνή λίστα προηγούμενων συνομιλιών, νήμα μηνυμάτων, παραδείγματα ερωτήσεων, optimistic αποστολή, έως 4.000 χαρακτήρες ανά μήνυμα.
- Απαντά απευθείας σε γενικές μελισσοκομικές ερωτήσεις· για ερωτήσεις για συγκεκριμένη κυψέλη **τρέχει τη διάγνωση του Rules Engine** ή/και **φέρνει πρόσφατες τάσεις** μέσω εργαλείων και δεν επινοεί ποτέ συστάσεις που δεν επέστρεψαν τα εργαλεία (βλ. §5.3).
- Οι συνομιλίες αποθηκεύονται και μπορούν να διαγραφούν (soft-delete).

### 3.11 Καιρός (μέσα στην προβολή μελισσοκομείου)
- Πρόγνωση 7 ημερών συν ωριαίος πίνακας σήμερα για τις συντεταγμένες του μελισσοκομείου: θερμοκρασία, υγρασία, ταχύτητα/ριπές/κατεύθυνση ανέμου, πιθανότητα και ύψος βροχής, δείκτης UV, νεφοκάλυψη, πίεση, ανατολή/δύση. Από το **Tomorrow.io**, μέσω proxy και cache (10 λεπτά) στο backend ώστε το κλειδί να μένει server-side. Εμφανίζει «Set apiary coordinates to enable weather» όταν ένα μελισσοκομείο δεν έχει συντεταγμένες.

### 3.12 Ειδοποιήσεις (καμπανάκι κεφαλίδας)
- Παράγονται καθημερινά στις 08:00 από το backend για θεραπείες: **«Overdue: {θεραπεία}»** για προγραμματισμένες δόσεις που πέρασε η ημερομηνία τους και **«Upcoming: {θεραπεία}»** για δόσεις που λήγουν εντός 7 ημερών («Due today / in N days»). Ιδεμποτικές· οι παρωχημένες αφαιρούνται όταν ολοκληρωθεί η δόση.
- Badge μη αναγνωσμένων (όριο 99+), σήμανση μίας / όλων ως αναγνωσμένων.

### 3.13 Προφίλ (`/user/profile`)
- Κάρτα λογαριασμού (αρχικά, όνομα, «beekeeper · χώρα»), στοιχεία (όνομα, επώνυμο, χώρα, email μόνο για ανάγνωση, μονάδα, εμφάνιση υποδείξεων), διάλογος **αλλαγής κωδικού** (ζητά τον τρέχοντα κωδικό μόνο αν ο λογαριασμός έχει — οι λογαριασμοί μόνο με Google δεν έχουν).

## 5. Το επίπεδο νοημοσύνης (backend)

### 5.1 Rules Engine — διάγνωση επιθεώρησης
Αξιολογεί μία επιθεώρηση έναντι **παραμετροποιήσιμων κανόνων αποθηκευμένων στη βάση** και επιστρέφει δομημένη διάγνωση: λειτουργία (`normal` / `survival`), υπάρχοντες κίνδυνοι, συνιστώμενες ενέργειες, απαγορευμένες ενέργειες, δίγλωσση αιτιολόγηση (EN/EL) και βαθμό εμπιστοσύνης. Κάθε αξιολόγηση καταγράφεται με στιγμιότυπο των εισόδων της.

- Οι κανόνες έχουν συνθήκες (AND μέσα σε ομάδα, OR μεταξύ ομάδων), προτεραιότητα, κατηγορία (`hard`, `disease`, `structural`, `seasonal`, `optimization`) και συνδέσεις με **κατάλογο κινδύνων** και **κατάλογο ενεργειών**. Νέοι κανόνες δεν απαιτούν αλλαγές κώδικα.
- Όταν ενεργοποιούνται πολλοί κανόνες, μια **ενεργή προτεραιότητα** = βασική προτεραιότητα + ενισχύσεις από πρόσφατα ανιχνευμένες τάσεις καθορίζει τον νικητή (τάσεις υψηλής/κρίσιμης σοβαρότητας ενισχύουν κάθε κανόνα).
- **Προεγκατεστημένοι κανόνες (25):** Επείγον λιμοκτονίας χειμώνα · Ορφανό μελίσσι (κρίσιμο) · Ανίχνευση βαρρόα — απαιτείται θεραπεία · Ανίχνευση κελιών σμηνουργίας · Υγιής κυψέλη — έλεγχος ρουτίνας · Ανίχνευση αμερικανικής σηψιγονίας · Ανίχνευση ευρωπαϊκής σηψιγονίας · Σοβαρή κατάρρευση μελισσιού (καλοκαίρι) · Πολλαπλή συλλοίμωξη ασθενειών · Βαρρόα με αδύναμο πληθυσμό · Χειμερινή θεραπεία βαρρόα (χωρίς γόνο) · Ανοιξιάτικη θεραπεία βαρρόα (πριν τη νεκταροφορία) · Κρίσιμη θεραπεία βαρρόα πριν τον χειμώνα · Θεραπεία βαρρόα μετά τη συγκομιδή · Ανίχνευση νοσεμίασης · Υποψία ιογενούς λοίμωξης · Γερασμένη βασίλισσα — απαιτείται αντικατάσταση · Υποψία κηφηνοτόκου βασίλισσας · Αφύσικα χαμηλός γόνος σε δυνατό μελίσσι · Αδύναμο μελίσσι το καλοκαίρι · Ανισορροπία γόνου–πληθυσμού · Μελοδεμένη γονοφωλιά · Τάισμα πριν τον χειμώνα — κρίσιμο παράθυρο · Ρουτίνα φθινοπωρινής προετοιμασίας · Ανοιξιάτικη ανάπτυξη — απαιτείται διέγερση. *(Τα ονόματα στη βάση είναι αγγλικά· βλ. αγγλική έκδοση.)*
- **Κατάλογος κινδύνων (16):** λιμοκτονία μελισσιού, χειμερινή απώλεια μελισσιού, υψηλή προσβολή βαρρόα, υποψία AFB, υποψία EFB, νοσεμίαση, ορφανό μελίσσι, αποτυχία βασίλισσας, επικείμενη σμηνουργία, κατάρρευση μελισσιού, αδύναμο μελίσσι, κίνδυνος εγκατάλειψης, υπερθέρμανση κυψέλης, κίνδυνος λεηλασίας, απαιτείται ενημέρωση αρχών, υποψία ιογενούς λοίμωξης — καθένας με σοβαρότητα (medium / high / critical).
- **Κατάλογος ενεργειών (32):** επείγον τάισμα με ζαχαρόπαστα, τάισμα με σιρόπι, τάισμα με υποκατάστατο γύρης, θεραπεία βαρρόα με οξαλικό / θυμόλη / μυρμηκικό οξύ, αναφορά στις κτηνιατρικές αρχές, απομόνωση κυψέλης, καταστροφή κυψέλης (κανονιστική), ελαχιστοποίηση ενόχλησης, πλήρης επιθεώρηση, συνέχιση παρακολούθησης, επαλήθευση παρουσίας βασίλισσας, προσθήκη ορόφου, αφαίρεση βασιλικών κελιών, διαίρεση κυψέλης, ένωση με δυνατή κυψέλη, εισαγωγή νέας βασίλισσας, προσθήκη πλαισίου γόνου, μείωση χώρου κυψέλης, μόνωση για τον χειμώνα, παροχή νερού, σκίαση, στένωση εισόδου, επανέλεγχος σε 3 / 7 ημέρες, συμβουλή ειδικού, μέτρηση βαρρόα, θεραπεία νοσεμίασης, αντικατάσταση παλιών κηρηθρών, τρύγος μελιού, εγκατάσταση/έλεγχος βασιλικού διαφράγματος.

### 5.2 Trend Engine — μοτίβα σε πολλές επιθεωρήσεις
Αναλύει το ιστορικό επιθεωρήσεων μιας κυψέλης σε ένα παράθυρο (προεπιλογή 60 ημέρες, ελάχιστο 3–4 επιθεωρήσεις) και αποθηκεύει τις τάσεις που ανιχνεύει με σοβαρότητα, κατεύθυνση, εμπιστοσύνη, σημεία δεδομένων και μια επισήμανση στα αγγλικά και στα ελληνικά. Ανιχνευτές:

| Τάση | Κατεύθυνση |
|---|---|
| Μείωση πληθυσμού | αρνητική |
| Χρόνια βαρρόα | αρνητική |
| Ταχεία ανάπτυξη (άνοιξη) | θετική |
| Διαταραχή γόνου (εκτός χειμώνα) | αρνητική |
| Αποτυχία θεραπείας | αρνητική |
| Ανάκαμψη μελισσιού | θετική |
| Αστάθεια βασίλισσας | αρνητική |

Οι τάσεις τροφοδοτούν το Rules Engine (ανακατάταξη κανόνων) και τον AI βοηθό (εργαλείο `get_recent_trends`).

### 5.3 AI βοηθός (επίπεδο LLM)
- Τρέχει σε **Ollama (llama3.1:8b)** με βρόχο κλήσης εργαλείων (έως 5 επαναλήψεις). Εργαλεία: `run_diagnostic` (Rules Engine), `get_recent_trends` (Trend Engine), `explain_analysis` (μορφοποίηση διάγνωσης), `request_clarification` (ζητά την κυψέλη όταν λείπει).
- Κανόνες του system prompt: απαντά απευθείας σε εκπαιδευτικές ερωτήσεις· για συγκεκριμένη κυψέλη τρέχει πάντα πρώτα τη διάγνωση· δεν επινοεί ποτέ θεραπείες· κρατά τις απαντήσεις σύντομες· διατηρεί το πλαίσιο της συνομιλίας (θυμάται σε ποια κυψέλη αναφέρεται το «αυτή» και επαναχρησιμοποιεί προηγούμενα αποτελέσματα εργαλείων).
- Περικοπή ιστορικού σε context 8k tokens, αυτόματοι τίτλοι συνομιλιών, κάθε κλήση εργαλείου ελέγχεται (ορίσματα, αποτέλεσμα, χρόνος).
- **Αξιολόγηση ποιότητας** (από admin ή αυτόματα με `JUDGE_AUTO`): το Claude Haiku 4.5 βαθμολογεί κάθε απάντηση σε ακρίβεια γεγονότων, ορθότητα εργαλείων, καταλληλότητα άρνησης, χρησιμότητα, συν σημαίες παραίσθησης και ασφάλειας· όταν έτρεξε διάγνωση, η έξοδος του Rules Engine εισάγεται ως ground truth ώστε να εντοπίζονται επινοημένοι κίνδυνοι/ενέργειες. Ημερήσιο όριο κόστους, prompt caching, σημειώσεις ελέγχου admin και «flag for retraining».
- Υπάρχει pipeline παραγωγής dataset (Claude API, θεματικοί σπόροι για διαγνωστικές / εκπαιδευτικές / διευκρινιστικές / πολυ-γυρικές / αρνητικές περιπτώσεις) για δεδομένα εκπαίδευσης/αξιολόγησης.

## 6. Η mobile εφαρμογή — φωνητική καταγραφή στο χωράφι

### 6.1 Σκοπός και εμβέλεια
Η εφαρμογή κάνει ένα πράγμα: **καταγράφει επιθεωρήσεις και συγκομιδές με τη φωνή, offline, και τις συγχρονίζει με τον λογαριασμό**. Δεν υπάρχουν γραφήματα, θεραπείες ή οικονομικά στο κινητό — αυτά ζουν στο web. Σύνθημα στην οθόνη καλωσορίσματος: *«Let the Record Begin»*.

### 6.2 Οθόνες
- **Launcher** (splash) → **Onboarding** (4 διαφάνειες: Welcome · Specify your bees' features · Manage your colonies · Enable microphone) → **Welcome / Welcome back** → **Login / Sign up** (email+κωδικός ή Google).
- Μπάρα καρτελών: **Record · Commands · Sync · More**.
  - **Record**: επιλογή λειτουργίας (Inspection / Harvest), ημερομηνίας και μελισσοκομείου· πατάς το μικρόφωνο και λες αριθμό κυψέλης· η οθόνη γυρίζει σε «Recording — Beehive N» και η λίστα πεδίων (Population, Frames, Pollen, Nectar, Eggs, Closed Brood, Queen, Diseases) γεμίζει καθώς αναγνωρίζονται οι φράσεις. Το «Finish and save» βάζει τα πάντα στην ουρά και ανεβάζει αν υπάρχει σήμα («Saved to your account» / «Saved on this device — N waiting for signal»).
  - **Commands**: αναφορά με το τι μπορείς να πεις, ομαδοποιημένη (Frames, Pollen, Nectar, Eggs, Closed Brood, Queen, Diseases· Harvest: Honey).
  - **Sync (Pending sync / outbox)**: η ουρά καταγραφών που περιμένουν ή απέτυχαν (π.χ. «No beehive named “23” in this apiary»), με Retry και Discard.
  - **More**: Help, Rate us, Voice training, Settings, Log out.
- **Voice training**: μαθαίνεις στον αναγνωριστή πώς *εσύ* προφέρεις κάθε λέξη-κλειδί (beehive, frames, pollen, honey, brood, varroa, nosema)· μια λέξη θεωρείται «μαθημένη» μετά από τέσσερις συνεπείς αναγνωρίσεις, και οι διορθώσεις εφαρμόζονται σε κάθε μελλοντικό transcript.
- **Settings**: μπιπ μετά την εντολή, ειδοποιήσεις, αξιολόγηση, κοινοποίηση εφαρμογής. **Help**: 6 βήματα + συμβουλές. **Rate**: χαμηλή βαθμολογία ανοίγει ιδιωτική ανατροφοδότηση, υψηλή παραπέμπει σε κριτική στο store.

### 6.3 Φωνητική γραμματική (μόνο αγγλικά)
| Λες | Αποτέλεσμα |
|---|---|
| "beehive number twelve" / "beehive number 12" | Επιλέγει την κυψέλη· ό,τι ακολουθεί αφορά αυτήν |

| "five frames population" / "… of population" | Πλαίσια καλυμμένα από μέλισσες |
| "two frames of pollen", "half a frame of pollen", "zero point four frames of pollen" | Γύρη (επιτρέπονται κλάσματα· τα ποσά **αθροίζονται** καθώς φωνάζεις κάθε πλαίσιο) |
| "three frames of nectar" | Μέλι/νέκταρ |

### 6.4 Offline-first συγχρονισμός
- Κάθε πρόχειρο γράφεται στην αποθήκευση της συσκευής σε κάθε αλλαγή, οπότε μια άδεια μπαταρία ή ένα crash δεν κοστίζει τίποτα.
- Τα πρόχειρα μπαίνουν σε ουρά, ανεβαίνουν μόνο όταν υπάρχει δίκτυο και **αφαιρούνται μόνο αφού ο server τα επιβεβαιώσει**. Οι αποτυχημένες αποστολές μένουν στην ουρά με τον λόγο.
- Οι αριθμοί κυψελών αντιστοιχίζονται με τα ονόματα κυψελών του μελισσοκομείου τη στιγμή του συγχρονισμού.
- Η αποσύνδεση κρατά τις μη συγχρονισμένες καταγραφές στη συσκευή.
